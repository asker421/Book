# MAXIMUM CAUTION AUDIT PROTOCOL — «Красная будка»

Этот документ является обязательным fail-closed протоколом максимальной осторожности для аудита художественного корпуса V3.

Он действует поверх обычного chapter audit и запрещает объявлять главу VERIFIED на основании общего впечатления, выборочной проверки или предыдущего PASS.

## 0. БАЗОВОЕ СОСТОЯНИЕ

Каждый новый аудит начинается только так:

**STATUS = FAIL / NOT VERIFIED**

Нельзя наследовать:
- предыдущий PASS;
- предыдущий CANON COVERAGE REGISTER;
- предыдущий voice pass;
- предыдущий physics/staging pass;
- предыдущий line-by-line pass;
- пользовательское одобрение;
- вывод «мы это уже проверяли».

Предыдущие worklog-записи разрешены только как история дефектов и правок, но не как доказательство текущего качества.

## 1. НИ ОДИН КАНОН НЕ ПРОВЕРЯЕТСЯ «В ЦЕЛОМ»

Каждый действующий canon / ledger / source-of-truth документ проверяется отдельно.

Для каждого файла необходимо:
1. открыть актуальную версию из current main;
2. извлечь все требования, применимые к текущей главе;
3. проверить каждое требование отдельно;
4. найти конкретное evidence в тексте или доказать N/A;
5. проверить запреты;
6. проверить соседние continuity/payoff-сцены, если файл этого требует;
7. только после этого присвоить самому файлу PASS / FAIL / N/A.

Формат доказательства:

- CANON / SOURCE
- применимое требование
- evidence
- status

Запрещено ставить:
- «персонажи — PASS»;
- «голоса — PASS»;
- «физика — PASS»;
- «каноны соблюдены»,

если не проверены все применимые требования соответствующих файлов.

## 2. CHARACTER VOICE — КАЖДАЯ РЕПЛИКА ОТДЕЛЬНО

Каждая реплика каждого персонажа является отдельным объектом проверки.

Для каждой реплики обязательны:
- speaker;
- текущее эмоциональное состояние;
- конкретный voice mode из CHARACTER_VOICE_CANON.md;
- доступное знание;
- непосредственная цель реплики;
- причина произнесения именно сейчас;
- длина и ритм фразы;
- синтаксис;
- словарь;
- юмор / отсутствие юмора;
- допустимая степень точности;
- отсутствие авторского голоса;
- отсутствие слишком умной или слишком информированной формулировки;
- отсутствие преждевременного знания;
- отсутствие искусственного Chekhov setup.

Обязательный вопрос:

**Сказал бы именно этот персонаж именно эту фразу именно в этом состоянии, если бы автор не знал, что произойдёт через следующий абзац?**

Формат:

REPLICA: «...»
Speaker:
State:
Voice mode:
Knowledge:
Immediate goal:
Why now:
Voice match:
Knowledge match:
Motivation match:
No-Chekhov:
Verdict: PASS / FAIL

Запрещено:
- объединять несколько реплик;
- ставить PASS диалогу по общему впечатлению;
- считать естественную реплику автоматически голосовой;
- считать голос проверенным по нескольким характерным примерам.

Одна реплика FAIL = вся глава FAIL.

## 3. КАЖДОЕ ПОВЕСТВОВАТЕЛЬНОЕ ПРЕДЛОЖЕНИЕ / МИКРОДЕЙСТВИЕ ОТДЕЛЬНО

Для каждого повествовательного предложения, внутренней реакции, авторской ремарки, микродействия, вывода, сравнения, сенсорного наблюдения и перехода проверить:

1. POV;
2. observability;
3. physics;
4. staging;
5. положение тела;
6. руки / ноги / занятость рук;
7. дверь / порог / предметы / телефон / трубка / провод;
8. causal continuity;
9. knowledge source;
10. reveal order;
11. reaction realism;
12. voice, если это внутренняя формулировка персонажа;
13. narrative style;
14. author style;
15. self-proof;
16. writing tics;
17. No-Chekhov / author foreknowledge;
18. continuity с предыдущей и следующей единицей;
19. later payoff compatibility;
20. literary necessity.

Нельзя объединять несколько предложений в PASS, если хотя бы одно из них не проверено отдельно.

## 4. PHYSICS / MICRO-STAGING — ПОКАДРОВО

Для каждой смены положения обязательно установить:
- точную позицию персонажа;
- сторону порога;
- состояние двери;
- положение головы/взгляда;
- положение обеих рук;
- положение обеих ног, если движение зависит от них;
- занятость рук предметами;
- положение мобильного;
- положение трубки;
- состояние и допустимую длину шнура;
- расстояние до стен/рамы/других персонажей;
- реальные линии зрения;
- слышимость;
- состояние внешней среды.

Запрещено подразумевать ранее не установленную позицию части тела или предмета.

Отдельные обязательные запреты:
- gait/posture inference до достаточного числа наблюдаемых шагов;
- gaze attribution без доступной геометрии;
- hidden hand movement;
- hidden object transfer;
- hidden threshold crossing;
- движение через препятствие без промежуточного физического шага;
- история температуры/предмета/состояния, которую POV не может знать.

Один micro-staging FAIL = вся глава FAIL.

## 5. KNOWLEDGE AUDIT — КАЖДЫЙ ФАКТ

Каждая фактическая формулировка в narration и dialogue получает источник:

- OBSERVED
- REPORTED
- INFERRED
- HYPOTHESIS
- MISBELIEF
- CONFIRMED

Если источник нельзя указать — KNOWLEDGE FAIL.

Особенно строго:
- Катя знает только то, что услышала/увидела/получила в своей линии;
- сервисная сторона знает только доступные ей сигналы;
- Асгар не получает позднюю механику раньше времени;
- close-third narrator не знает больше POV;
- никакая технология не создаёт информацию без физического канала.

## 6. MOTIVATION / ANTI-IDIOT — КАЖДОЕ ЗНАЧИМОЕ ДЕЙСТВИЕ

Для каждого существенного действия:
- чего персонаж хочет;
- что знает;
- чего боится;
- какие альтернативы видит;
- почему выбирает именно это;
- почему не выбирает очевидно более безопасный/простой вариант;
- какое изменение в сцене запустило действие.

Если честный ответ:
**«иначе не произойдёт следующая сцена»** — FAIL.

## 7. NO-CHEKHOV / AUTHOR FOREKNOWLEDGE

Каждую реплику и действие проверять вопросом:

**Возникло бы это естественно, если бы автор не знал следующий beat?**

Особенно подозрительны:
- «я тебя знаю»;
- «ты опять...»;
- «только не...»;
- «не вздумай...»;
- предупреждение о действии, которое ещё ничем не подготовлено;
- внезапный вопрос ровно перед нужным reveal;
- внимание к предмету только потому, что он понадобится через строку;
- слишком точная догадка без наблюдаемого основания.

Искусственная подготовка следующего beat = FAIL.

## 8. VOICE PASS НЕ РАВЕН «ДИАЛОГ ХОРОШИЙ»

Реплика может быть:
- естественной;
- логичной;
- грамотной;
- красивой;

и всё равно получить VOICE FAIL.

PASS разрешён только после доказательства, что эту формулировку произнёс бы именно этот человек в текущем эмоциональном и когнитивном состоянии.

## 9. ЛЮБОЙ FAIL ПОЛНОСТЬЮ ОБНУЛЯЕТ ТЕКУЩИЙ RUN

Если найден хотя бы один FAIL:

1. вся глава немедленно получает FAIL;
2. исправляется только доказанный дефект;
3. новая версия сохраняется;
4. актуальный текст заново открывается из current main;
5. ВСЕ PASS текущего run уничтожаются;
6. аудит начинается заново с первого канона;
7. заново проверяется полный canon stack;
8. заново выполняется полный line-by-line;
9. заново выполняется полный replica-by-replica voice audit;
10. заново выполняется mechanical scan;
11. заново выполняются continuity/payoff gates;
12. заново считается точный word count.

Продолжение «с места ошибки» запрещено.

## 10. ОБЯЗАТЕЛЬНЫЙ DOUBLE-BLIND / ADVERSARIAL FINAL AUDIT

Даже когда первый полный непрерывный run завершился:

**FAIL count = 0**

глава ещё НЕ VERIFIED.

Нужно немедленно провести второй независимый полный audit run с нуля.

Во втором run считать:
- текст написан другим автором;
- результат первого run неизвестен;
- прошлых PASS не существует;
- задача — не подтвердить, а опровергнуть первый PASS;
- специально искать скрытый counterexample для каждого канона, каждой реплики и каждой физической цепочки.

Второй run обязан снова пройти:
- весь canon/source stack;
- каждое применимое требование;
- каждую строку;
- каждую реплику;
- каждое микродействие;
- voice-state mapping;
- knowledge;
- motivation;
- physics/staging;
- continuity/payoff;
- prose/style;
- mechanical scan;
- exact word count.

Только если второй независимый run также завершился:

**FAIL count = 0**

глава может получить:

**VERIFIED — DOUBLE AUDIT PASS**

Если второй run находит хотя бы один FAIL, применяется обычный полный reset после исправления. Счёт двух чистых run начинается заново.

## 11. ФИНАЛЬНЫЙ ОТЧЁТ — ДОКАЗАТЕЛЬНЫЙ

До статуса VERIFIED отчёт обязан содержать:
1. все FAIL, найденные за цикл;
2. точную дефектную строку/реплику;
3. нарушенный canon/source;
4. причину FAIL;
5. хирургическое исправление;
6. число полных reset;
7. полный CANON COVERAGE REGISTER;
8. число проверенных строк;
9. число проверенных реплик;
10. число sentence/action units;
11. число непроверенных единиц — обязательно 0;
12. FIRST FULL RUN FAIL count;
13. SECOND ADVERSARIAL FULL RUN FAIL count;
14. final chapter content SHA;
15. commit SHA;
16. exact word count;
17. точное exit state;
18. continuity с соседней главой;
19. обязательные поздние payoff gates;
20. факт пользовательского одобрения или его отсутствия.

Если любой обязательный пункт не доказан:

**NOT VERIFIED**

## 12. ЗАПРЕТ ЛОЖНОГО PASS

Лучше оставить главу FAIL, чем поставить PASS на основании:
- общего впечатления;
- памяти;
- старого worklog;
- старого PASS;
- пользовательского одобрения;
- хорошего качества прозы;
- отсутствия очевидных дефектов;
- выборочной проверки;
- проверки нескольких характерных реплик;
- группового PASS для канона;
- одного чистого audit run.

**PASS = доказательство по каждой применимой норме.**

Если доказательства нет — PASS запрещён.

## 13. ПРИОРИТЕТ

Этот протокол обязателен для всех новых cold-start аудитов V3.

Если более старый audit/worklog/progress статус объявляет главу VERIFIED, но она не прошла обязательный double-audit по этому протоколу после даты его введения, такой VERIFIED считается **LEGACY / NOT VERIFIED UNDER MAXIMUM CAUTION** до нового полного цикла.

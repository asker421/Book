# 1. Source of truth

Перед любой правкой:
- получить свежий `main`;
- прочитать текущий `chapters_v4/`-файл целиком;
- прочитать соседние активные главы;
- открыть релевантные каноны;
- при финальной механике обязательно применять `FINAL_CANON_OVERRIDE.md`.

Если другой агент изменил файл после начала работы — перечитать новый blob перед записью.

Нельзя:
- восстанавливать старую сцену по памяти;
- брать V2/V3 как текстовый шаблон;
- считать старый worklog доказательством PASS;
- переносить удалённые эпохи обратно в V4.

# 3. Письмо и правка

Любая новая или переписанная сцена обязана одновременно соблюдать:
- причинность;
- физику;
- staging;
- знание персонажей;
- reveal order;
- мотивацию;
- anti-idiot;
- голос;
- отношения;
- состояние тела/инвентаря;
- язык/канал связи;
- reader experience;
- prose/style/tics.

Нельзя писать сначала «скелет событий», а потом механически приклеивать эмоции и диалоги.

Важное событие должно быть прожито на странице, а не сообщено пересказом.

# 6. Git / сохранение

Для активной V4 действует явное разрешение автора сохранять правки в `main` без повторного запроса, если задача прямо требует правки корпуса/документации.

После изменения:
- не перетирать более свежий blob;
- синхронизировать зависимые canon/ledger-файлы в том же цикле, если изменилась каноническая механика;
- не объявлять литературный PASS по факту успешного commit/build.

# MASTER ROMAN AUDIT — «Красная будка» v3

## Статус

Это единая обязательная процедура проверки `chapters_v3/`.

Она не создаёт новый сюжетный канон. Она заставляет проверять уже существующие каноны в правильном порядке.

Главный принцип:

> глава не получает PASS, пока не проходит все релевантные слои без CRITICAL/MAJOR ошибок.

Нельзя считать главу проверенной только потому, что она локально хороша: выход предыдущей и вход следующей должны совпадать.

# 3. PASS 1 — CHAPTER CONTRACT

Проверить:
- функция главы выполнена;
- все обязательные события присутствуют;
- обязательное изменение произошло;
- запрещённые события отсутствуют;
- состояние на выходе правильное.

Любой hard prohibition = **CRITICAL**.

---

# 4. PASS 2 — CAUSE / EFFECT

Для каждого существенного события:
- назвать причину;
- проверить, где она установлена;
- проверить немедленное следствие;
- проверить отложенные последствия;
- убедиться, что предыдущая причина не забыта.

Особое внимание:
- дверь 2014;
- пассажирская запись;
- повторные окна;
- 2039;
- Ар;
- 22 месяца;
- историческая адресация;
- молчание старшего;
- однозначность нагрузки.

---

# 5. PASS 3 — KNOWLEDGE

Для каждой значимой реплики/мысли:
- кто знает;
- откуда;
- статус знания;
- когда получил;
- не из будущей ли главы;
- не услышал ли закрытый разговор;
- не увидел ли невозможное.

Факт без источника = **KNOWLEDGE FAIL**.

---

# 6. PASS 4 — REVEAL ORDER

Проверить:
- не назван ли RETRO-1 до гл.31;
- не появляются ли операторы в основном POV до гл.16;
- не подтверждён ли мужчина=Асгар до гл.35;
- не раскрыта ли историческая апертура до гл.34;
- не объяснён ли финальный 2039 раньше времени.

---

# 8. PASS 6 — TIME CONTINUITY

Проверить отдельно:
- внешний календарь;
- реально прожитое время;
- биологическое старение;
- длительность обучения;
- длительность отношений.

Миллионы календарных лет не старят Асгара автоматически.

---

# 9. PASS 7 — MOTIVATION

Для каждого крупного решения:
- чего хочет персонаж;
- какой новый факт;
- риск;
- альтернатива;
- почему не выбрал безопаснее;
- свободен ли отказаться;
- эмоциональная цена.

Если ответ: «иначе не будет следующей главы» = FAIL.

---

# 9A. PASS 7A — ANTI-IDIOT / INTERACTION CAUSALITY

Источник: `CHARACTER_MOTIVATION_ANTI_IDIOT_CANON.md`.

Проверить: почему каждый значимый персонаж находится в сцене; как узнал о событии; зачем подошёл, заговорил, проверил, помог, отказал или вмешался; почему не выбрал очевидную альтернативу; не существует ли взаимодействие только потому, что сюжету нужен следующий шаг.

Любой необоснованный контакт = **ANTI-IDIOT FAIL**.

# 9B. PASS 7B — HUMAN CONFLICT / ANTAGONISM

Источник: `CONFLICT_ANTAGONISM_CANON.md`.

Проверить: не помогают ли Асгару все по умолчанию; есть ли у людей самостоятельные цели; естественно ли человеческое противодействие; не возник ли «антагонист недели»; не закрывается ли каждый конфликт примирением; не знает ли противник лишнего; не действует ли он глупо ради сюжета; синхронизированы ли history/voice/knowledge/relationship canons; остаются ли последствия.

Нарушение = **HUMAN CONFLICT CANON FAIL**.

# 9C. PASS 7C — ASGAR FLAW / SHADOW

Источник: `ASGAR_FLAW_CANON.md`.

Проверить:
- не является ли Асгар безошибочным аналитиком/моральным центром по умолчанию;
- есть ли разрыв между рациональным объяснением и полным мотивом;
- имеет ли другой персонаж право быть правым против него;
- не оправдана ли ложь/манипуляция рассказчиком;
- сохраняются ли последствия;
- проходят ли обязательные теневые узлы глав 8, 22, 23, 30, 33 и 35;
- не превращена ли поздняя зрелость в врождённую идеальность.

Нарушение = **ASGAR FLAW CANON FAIL**.

# 15A. PASS 13A — CHARACTER REVEAL / PAST AROMA

Для каждого факта прошлого, попавшего на страницу:
- факт существует в `CHARACTER_HISTORY_CANON.md`;
- глава разрешена `CHARACTER_REVEAL_MAP.md`;
- источник знания совместим с `KNOWLEDGE_LEDGER.md`;
- reveal не нарушает `CHAPTER_BY_CHAPTER_CANON.md`;
- до причины есть наблюдаемый след;
- причина всплывает из давления текущей сцены;
- факт влияет на решение, конфликт, отношение или payoff;
- backstage остаётся backstage, если сцене он не нужен.

Критические ошибки:
- биографическая справка вместо сцены;
- прошлое раскрыто раньше своей точки;
- Асгар знает читательский/backstage reveal без источника;
- травма автоматически оправдывает действие;
- новый персонаж получает полную биографию при первом появлении.

Специальный firewall:
- глава 33: только стук/неопознанный человеческий силуэт;
- глава 34: первое имя, голос, профессия и человеческая конкретика Сабины.

Нарушение границы главы = **CRITICAL CHARACTER REVEAL FAIL**.

# 18. PASS 16 — FORESHADOWING / PAYOFF

Для каждого clue:

- не исчез ли;

Для каждого payoff:
- seed;

# 19. PASS 17 — READER EXPERIENCE

Проверить:

- реакция соответствует масштабу;
- новый класс невозможного ощущается новым;
- эмоциональное последствие переносится дальше.

# 20. PASS 18 — PROSE / DIALOGUE

---

# 23. REPAIR LOOP

Если найден FAIL:

1. определить минимальный причинный радиус;
2. исправить только необходимое;
3. не добавлять новый канон для лечения локальной ошибки;
4. повторить **все passes, которые правка могла затронуть**;
5. если правка меняет knowledge/state/foreshadow/staging — синхронизировать соответствующий ledger;
6. глава получает PASS только после повторной проверки.

# 24. СТЕПЕНИ ОШИБКИ

## CRITICAL
Ломает:
- финальную механику;
- worldline;
- reveal-order;
- ключевую причинность;
- 1↔35;
- 8↔35;
- пассажирскую запись;
- физическую возможность сцены.

## MAJOR
Не ломает весь роман, но нарушает:
- мотивацию;
- знания;
- голос;
- отношения;
- эпохальную способность;
- значимый foreshadowing.

## MINOR
Локальная:
- формулировка;
- staging detail;
- повтор;
- слабая телесная реакция;
- терминологическая неточность без причинного эффекта.

# 26. FINAL NOVEL PASS

Роман готов только если одновременно:

- нет CRITICAL;
- нет нерешённых MAJOR;
- все 35 глав + 5 интерлюдий прошли contract;
- все ledgers синхронизированы с v3;
- финал технически следует из правил, существовавших раньше;
- читатель может перечитать главу 1 после главы 35 и увидеть ту же физическую сцену;
- ни один персонаж не знает невозможного;
- ни одна эпоха не получает удобную сверхспособность;
- Асгар остаётся одним непрерывным человеком;
- RETRO-1 завершает свою задачу;
- пассажирская задача остаётся незакрытой;
- после канонической финальной строки нет sequel-hook.

Только после этого допускается сборка печатной версии/EPUB как `release/`.

# 27. PASS 21 — HUMAN CONFLICT / ANTAGONISM

Этот pass обязателен после MOTIVATION, KNOWLEDGE и VOICE.

Проверить:
1. Нужен ли этой главе вообще персональный человеческий оппонент?
2. Предусмотрен ли он CONFLICT_ANTAGONISM_CANON.md?
3. Не повторяется ли конфликт предыдущей эпохи?
4. Если персонаж отрицательный — в чём его собственная выгода?
5. Если персонаж рационально спорит с Асгаром — не затемнил ли текст его без причины?
6. Не помогают ли все остальные слишком легко?
7. Не превращён ли любой отказ в злодейство?
8. Совпадает ли поведение с CHARACTER_HISTORY_CANON.md?
9. Совпадает ли речь с CHARACTER_VOICE_CANON.md?
10. Совпадает ли действие с CHARACTER_MOTIVATION_ANTI_IDIOT_CANON.md?
11. Есть ли источник знания в KNOWLEDGE_LEDGER.md?
12. Есть ли причинное следствие в CAUSE_EFFECT_LEDGER.md?
13. Не вытолкнул ли антагонист Асгара в следующий chapter beat вместо самостоятельного решения?
14. Не ощущается ли структура как «новая эпоха → новый враг»?

FAIL-категории:
- INSERTED VILLAIN FAIL;
- HELPFUL WORLD FAIL;
- ANTAGONIST KNOWLEDGE FAIL;
- ANTAGONIST VOICE FAIL;
- ANTAGONIST MOTIVATION FAIL;
- ANTAGONIST-OF-THE-WEEK FAIL;
- FORCED HERO DECISION FAIL.

После правки поведения конфликтного персонажа повторяются passes:
MOTIVATION → KNOWLEDGE → VOICE → RELATIONSHIPS → CAUSE/EFFECT → HUMAN CONFLICT.


# PASS — AUTHOR STYLE / CAUSAL ECHO

Перед финальным prose/tics pass сверить `CANON_AUTHOR_STYLE_V3.md`:
- следствие и объяснение появляются в психологически честном порядке;
- неизвестное не получает преждевременного имени;
- причинные эхо не декоративны;
- второй смысл ранних сцен не требует реткона;
- диалогический параллакс имеет мотивационную причину;
- эмоция меняет геометрию внимания;
- сенсорные швы совместимы с физикой;
- стиль не превратился в повторяемый трюк.

Любой **SECOND-READING CHEAT** или **POV OMNISCIENCE** = CRITICAL. Систематический **STYLE TIC** = MAJOR до исправления.

# 28. PASS 22 — PAIRWISE VOICE COLLISION

После обычного VOICE PASS обязательно выполнить попарную проверку всех говорящих в главе.

Для каждой пары:
1. Назвать уникальный речевой мотор каждого.
2. Сравнить длину фразы.
3. Сравнить тип синтаксиса.
4. Сравнить способ выражать страх.
5. Сравнить способ злиться.
6. Сравнить способ объяснять сложное.
7. Сравнить юмор.
8. Сравнить форму близости/уважения.
9. Убрать имена у 3–5 ключевых реплик и проверить, кто их произнёс.
10. Проверить VOICE COLLISION MATRIX из CHARACTER_VOICE_CANON.md.

Если хотя бы две ключевые реплики можно безболезненно переставить между персонажами — **VOICE COLLISION FAIL**.

Особый повышенный риск:
- Мариам ↔ Тавия ↔ Самир;
- Эстер ↔ Самир;
- Нурия ↔ Эмиль ↔ Лейла;
- Мариам ↔ Сабина ↔ предыдущая операторка;
- Йонас ↔ Тарик;
- Селин ↔ Северин;
- Рауф ↔ Вардан ↔ Кемаль.


# PASS — SYNC MATRIX / REWRITE STATUS

После каждого chapter pass сверить `CANON_SYNC_MATRIX.md`.

Глава не может получить FINAL PASS, если её строка остаётся `REWRITE REQUIRED` или `AUDIT REQUIRED`.

После главы 35 дополнительно проверить, что:
- все 40 художественных файлов имеют подтверждённый FULL V3 PASS;
- нет byte-identical seed-копий v2, ошибочно помеченных как переписанные;
- все изменения персонажей/голосов/мотиваций/cause-effect отражены в матрице.

Несоответствие = **GLOBAL SYNC MATRIX FAIL**.

# Рабочий промпт полного аудита главы — «Красная будка» V4

## Source of truth

Перед аудитом:
1. получить свежий `main`;
2. использовать только `chapters_v4/`;
3. прочитать проверяемую главу целиком;
4. прочитать соседние главы, если нужен вход/выход continuity;
5. загрузить `MANIFEST.md`, `V4_AUTHORING_RULES.md`, `FINAL_CANON_OVERRIDE.md` и все затронутые специализированные canon/ledger;
6. не использовать старый worklog или старый PASS как доказательство;
7. если blob изменился — аудит старого blob аннулируется.

Структура активной V4: **30 глав + 4 интерлюдии**.

---

# 1. Режим аудита

Читать как:
- холодный читатель;
- редактор;
- инженер физики сцены;
- adversarial canon checker.

Не искать ошибку ради ошибки.

Каждое замечание должно отвечать:
- что конкретно не работает;
- почему;
- какой canon/факт нарушен;
- насколько это серьёзно;
- требуется ли правка.

Классы:
- **CRITICAL** — ломает канон, причинность, финал, физику или понимание ключевого события;
- **MAJOR** — заметно ломает мотивацию, ясность, staging, голос, напряжение;
- **MINOR** — локальная шероховатость;
- **NOT A FAIL** — подозрение проверено и не подтвердилось.

---

# 2. Line-by-line gate

Для каждого абзаца/реплики спросить:
- зачем он здесь;
- откуда персонаж это знает;
- может ли это физически произойти;
- ясно ли, что происходит;
- не пересказано ли важное событие вместо сцены;
- не повторяет ли абзац уже понятую мысль;
- не добавляет ли автор скрытую информацию.

---

# 3. Chapter contract

Сверить с `CHAPTER_BY_CHAPTER_CANON.md`.

Проверить:
- функция главы;
- обязательные события;
- обязательный delta;
- запреты;
- exit state.

Если глава красиво написана, но не выполняет функцию — **CHAPTER CANON FAIL**.

- `HARD_SCENE_CANON.md`;
- `EPOCH_CAPABILITY_CANON.md`;
- `FINAL_CANON_OVERRIDE.md`.

# 6. Knowledge / reveal

- `KNOWLEDGE_LEDGER.md`;

Проверить:

- когда узнал;
- из какого канала;
- не знает ли рассказчик больше POV;
- не раскрыт ли термин раньше времени.

V4 firewall:

- мужчина 2014 = Асгар — физический payoff в главе 30;
- конкретный 2039-план — только после узла 2014;
- конкретный инвариант отказа — после фактического отказа 2039.

# 7. Cause / effect

Сверить `CAUSE_EFFECT_LEDGER.md`.

Для каждого крупного эффекта:
**причина → наблюдение → вывод → решение → последствие**.

Искать:
- необъяснённое движение;
- пропущенное звено;
- корреляцию, выданную за причину;
- позднюю причину, придуманную задним числом;
- исчезнувшее последствие.

# 10. Human reaction

Невозможное должно иметь цену реакции.

Проверить:
- шок;
- недоверие;
- попытку верификации;
- институциональную реакцию;
- последствия.

Нельзя:
- всем реагировать одинаково;
- всем мгновенно верить;
- всем быть полезными;
- повторно реагировать на уже знакомый класс события как впервые.

# 18. Формат результата

Для каждого подтверждённого дефекта:

### ПРОБЛЕМА N — [категория] — CRITICAL / MAJOR / MINOR
**Где:** глава, сцена, точная фраза/участок.  
**Что не работает:** конкретно.  
**Почему:** физика / канон / мотивация / читательская ясность.  
**Что должен понимать читатель:** результат.  
**Минимальный ремонт:** направление, без самовольного rewrite всей сцены.

Отдельно:
- **FALSE POSITIVES / NOT A FAIL**;
- **CANON/DOC DRIFT** — если ошибка в документации, а не в прозе;
- **VERDICT** — PASS только для точного текущего blob.

Любой CRITICAL/MAJOR оставляет главу без READY.
